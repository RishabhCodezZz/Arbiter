# Artifact guide

Model weights, transaction samples and local exports are ignored by Git. Run
[notebook 06](../notebooks/06_cost_model_refined.py) on Kaggle with competition data
attached and GPU enabled, then download its outputs into `artifacts/`. Complete the
final ensemble re-export: earlier cells write single-model dashboard/raw files that
the final addendum overwrites with current ensemble probabilities.

The engine averages independently Platt-calibrated Optuna-tuned XGBoost and untuned
LightGBM scores. The [evaluation report](../docs/eval_report.md) owns current results;
[experiments](../docs/experiments.md) records selection history and the
[economic source table](../docs/experiments.md#cost-model-parameters-and-provenance).
All monetary comparisons are simulations on the reused holdout under those assumptions.

## Required for ensemble scoring

| File | Contents |
|---|---|
| `model.json` | Native trained XGBoost model, using notebook 03's tuned configuration |
| `calibrator.json` | XGBoost Platt coefficients (`coef`, `intercept`) |
| `model_lgb.txt` | Native untuned LightGBM model |
| `calibrator_lgb.json` | LightGBM's independently fitted Platt coefficients |
| `feature_manifest.json` | Feature order, category vocabularies, kept V-columns and both training library versions |

Notebook 06 exports all five. The loader fails closed if either member is unavailable
or required schemas/versions are unsuitable. Use the library pins in
[requirements.txt](../requirements.txt). Runtime fingerprints are available;
expected checksum entries are optional and are not populated by the current export.

## Demo sample

`sample_transactions.json` contains 25 held-out raw transactions exported by notebook
06 for [demo_engine.py](../scripts/demo_engine.py). The sample is not needed for
arbitrary engine requests. The available random sample all scored allow under the
ensemble, so it cannot regenerate representative flagged queue/audit snapshots.

After placing the five model files and sample here, run from the repository root:

```powershell
# Windows
.\.venv\Scripts\python.exe scripts\demo_engine.py
```

```bash
# macOS/Linux
.venv/bin/python scripts/demo_engine.py
```

## Optional current evaluation exports

These notebook 06 outputs are not runtime model dependencies. Preserve them as the
source evidence for the current evaluation and dashboard.

| File | Purpose |
|---|---|
| `dashboard_data.json` | Current ensemble PR/ROC curves, two-way cost proxy and sensitivity grid; embedded in the offline page |
| `test_month_raw.json` | Current ensemble probabilities, labels and amounts for all 92,427 rows; input to [robustness_checks.py](../scripts/robustness_checks.py) |
| `ensemble_dashboard_headline.json` | Readable summary of the final ensemble dashboard/raw re-export |

The committed [robustness_results.json](../docs/robustness_results.json) records local
bootstrap and routing calculations from the raw export.

The raw export cell checks simulated headline value against its arrays. This checks
internal consistency, not observed profit or independent future-month performance.
[dashboard.html](../dashboard.html) already embeds its data and needs no local exports.

## Optional benchmark exports

`llm_benchmark_sample.json` is a historical 500-row sample pool; the retained LLM
comparison used 200 rows. `llm_benchmark_kaggle_results.json` contains LLM-side scores
from Ollama on Kaggle GPU. Their original benchmark cells were removed from notebook
04 and are not regenerated by current notebook 06. Preserve downloaded exports and
historical executed evidence when reproducing that work.

The current [benchmark script](../scripts/llm_benchmark.py) can consume Kaggle results,
but it now scores the ensemble. It does not reproduce the historical single-XGBoost
comparison. Historical reproduction also needs corresponding single-model artifacts
and aligned sample/results ordering; timeouts alter the compared row sets. See
[benchmark qualifications](../docs/experiments.md#historical-llm-benchmark-and-reproduction-limits).

## Retention

Keep trained models, manifests, result exports and paired notebook evidence, including
historical files no longer regenerated by current sources. Python/pytest caches and
local environment files are regenerable. Resetting `data/` loses client history and
audit records, which changes future feature state and duplicate-ID replay behavior.
Private notes are optional local context. No cleanup here authorizes deleting evidence
or runtime state; preserve or archive unique outputs before any separate cleanup.
